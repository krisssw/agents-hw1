# Отчёт: реализация build-tracker (попытка with-spec, OpenSpec)

Изменение: `openspec/changes/build-tracker`, схема spec-driven. Реализация выполнена через `/opsx-apply build-tracker`. Прогресс по tasks.md — **12/20**. Остальные 8 пунктов требуют ручной проверки в браузере, поэтому не отмечены.

## Что сделано

| Файл | Содержимое |
|---|---|
| `domain.mjs` | Чистые функции без DOM: `createInitialTasks`, `addTask`, `removeTask`, `toggleTask`, `computeMetrics` (прогресс по часам, при пустом списке — 0), `filterTasks` (all/active/done, неизвестное значение → all), `validateTaskInput` (trim, пустые часы ≠ 0, запятая, 0,5–24, шаг 0,5, обе ошибки сразу), `isValidTaskList` (проверка данных из хранилища). |
| `app.mjs` | Состояние `{tasks, filter}`. Рендер: список строится через `filterTasks`, итоги — через `computeMetrics` по всем задачам. Добавление с валидацией: при ошибке значения формы сохраняются, при успехе форма сбрасывается. Переключение статуса и удаление — через делегирование событий. Два варианта пустого состояния. Необязательный localStorage обёрнут в try/catch: при недоступном хранилище показывается сообщение, работа продолжается в памяти. |
| `index.html` | Форма `novalidate` с подписанными полями «Название» и «Часы». Ошибки выводятся рядом с полями (`aria-describedby`, `aria-invalid`). Блок итогов с `<progress>`, подписанный фильтр «Показать», список, область сообщений. Без CDN и внешних ресурсов. |
| `styles.css` | Mobile-first: `box-sizing: border-box`, `overflow-wrap: anywhere`, нет фиксированных ширин больше 390 px (только `max-width: 640px` у контейнера при `width: 100%`). |
| `tests/acceptance.test.mjs` | `node:test` + `node:assert/strict`: 32 теста в 7 группах (операции над данными, T1–T5, проверка данных хранилища). |

Согласованные правила R1–R6 и ожидаемые значения (25% → 75%, 8/2 ч, 0 ч/0%) не менялись.

**Расхождение с планом.** В артефактах была указана команда `node --test tests/`, но в Node 22.14 она падает: каталог воспринимается как модуль (`MODULE_NOT_FOUND`). Поэтому в tasks.md, design.md и proposal.md команда заменена на `node --test tests/acceptance.test.mjs`; правила и ожидаемые значения при этом не трогались. Простой `node --test` без аргументов тоже находит тесты. После правки `openspec validate build-tracker --strict --no-interactive` → valid.

4. Статически: все id, к которым обращается `app.mjs`, есть в `index.html`; в html/css/mjs нет внешних URL и CDN.
5. Дымовой прогон `app.mjs` в Node на самописной заглушке DOM (временный скрипт вне проекта; **это не браузер**, вёрстка и реальные события не проверялись). localStorage подменён объектом, который выбрасывает ошибку. Результаты:

   - «Практика» → 8/6/75%, обратно → 25%;
   - фильтр «active» → 2 задачи, итоги остаются 25%;
   - «Лабораторная» / −2 → задача не добавлена, ошибка у поля часов, значения в полях сохранены, `aria-invalid="true"`;
   - «0,5» → добавлено (8,5/2/24%), ошибка скрыта, форма сброшена;
   - удаление всех → 0/0/0%, «Задач нет — добавьте первую.», без NaN/Infinity; новая задача после этого добавляется (4/0/0%).

**Браузер не запускался.** Отрисовка, ширина 390 px, фокус, реальные клики и консоль браузера не проверены.
