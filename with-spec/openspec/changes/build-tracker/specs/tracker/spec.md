# Spec Delta

## Purpose

Трекер позволяет студенту вести список учебных задач на неделю, отмечать выполнение и видеть общий объём и прогресс по часам, работая автономно в браузере без сервера и внешних зависимостей.

## ADDED Requirements

### Requirement: Задача и стартовый набор
Каждая задача MUST иметь поля `id` (уникальный), `title` (строка), `hours` (число) и `done` (логическое). При первом запуске трекер MUST содержать стартовый пример: «Чтение» 2 ч, done=true; «Практика» 4 ч, done=false; «Повторение» 2 ч, done=false.

#### Scenario: Исходный пример (T1)
- **WHEN** трекер открыт со стартовыми задачами
- **THEN** в списке 3 задачи, всего 8 ч, выполнено 2 ч, прогресс 25%
- **AND** прогресс считается по часам, а не по числу задач (не 33%)

### Requirement: Добавление задачи
Система MUST добавлять задачу с корректными названием и часами в данные и показывать её в списке. Новая задача MUST получать уникальный `id` и `done=false`, а метрики MUST пересчитываться.

#### Scenario: Добавление корректной задачи
- **WHEN** в стартовом наборе пользователь добавляет задачу «Конспект» на 2 ч
- **THEN** в данных и в списке 4 задачи, всего 10 ч, выполнено 2 ч, прогресс 20%

### Requirement: Удаление задачи
Система MUST удалять выбранную задачу из данных и из списка; метрики MUST пересчитываться по оставшимся задачам.

#### Scenario: Удаление одной задачи
- **WHEN** в стартовом наборе пользователь удаляет «Повторение»
- **THEN** остаются 2 задачи, всего 6 ч, выполнено 2 ч, прогресс 33%

### Requirement: Переключение статуса
Переключение статуса задачи MUST менять поле `done` в данных и отображение задачи в интерфейсе; метрики MUST пересчитываться сразу. Повторное переключение MUST возвращать прежнее значение.

#### Scenario: Отметить «Практику» выполненной (T2)
- **WHEN** в стартовом наборе пользователь отмечает «Практику» выполненной
- **THEN** у «Практики» done=true, выполнено 6 из 8 ч, прогресс 75%
- **AND** в интерфейсе задача отображается как выполненная

#### Scenario: Снять отметку
- **WHEN** пользователь повторно переключает статус «Практики»
- **THEN** done=false, выполнено 2 из 8 ч, прогресс 25%

### Requirement: Валидация названия
Название MUST быть непустым после удаления пробелов по краям (trim). Сохраняемое название MUST быть обрезанным. Некорректная задача MUST NOT добавляться.

#### Scenario: Пустое название
- **WHEN** пользователь отправляет форму с пустым названием и часами 2
- **THEN** задача не добавляется, рядом с полем названия видна ошибка

#### Scenario: Название из пробелов
- **WHEN** пользователь отправляет название «   » и часы 2
- **THEN** задача не добавляется, рядом с полем названия видна ошибка

### Requirement: Валидация часов
Часы MUST быть конечным числом от 0,5 до 24 включительно с шагом 0,5. Пустое значение MUST считаться ошибкой и MUST NOT трактоваться как 0. Нечисловые, отрицательные, нулевые и вне диапазона значения MUST отклоняться.

#### Scenario: Пустые часы
- **WHEN** пользователь отправляет название «Тест» с пустым полем часов
- **THEN** задача не добавляется, рядом с полем часов видна ошибка

#### Scenario: Отрицательные часы
- **WHEN** пользователь отправляет часы -1
- **THEN** задача не добавляется, рядом с полем часов видна ошибка

#### Scenario: Границы диапазона и шаг
- **WHEN** пользователь отправляет часы 0,5 или 24
- **THEN** значение принимается
- **WHEN** пользователь отправляет часы 0, 24,5 или 1,3
- **THEN** задача не добавляется, видна ошибка у поля часов

### Requirement: Сохранение введённых данных при ошибке
При ошибке валидации форма MUST сохранять введённые пользователем значения, а ошибка MUST отображаться рядом с соответствующим полем и быть связана с ним. После успешного добавления ошибки MUST скрываться.

#### Scenario: Значения формы сохраняются (T4)
- **WHEN** пользователь отправляет название «Лабораторная» и часы -2
- **THEN** задача не добавляется, в полях остаются «Лабораторная» и -2, у поля часов видна ошибка

### Requirement: Расчёт прогресса
Система MUST показывать всего часов, выполненные часы и прогресс = округление(100 × сумма часов done / сумма часов всех задач) в процентах. Значения MUST быть конечными числами.

#### Scenario: Прогресс по часам
- **WHEN** задачи: 2 ч done, 4 ч не done, 2 ч не done
- **THEN** прогресс 25%

### Requirement: Пустое состояние
Если задач нет, система MUST показывать всего 0 ч, выполнено 0 ч и прогресс 0% без NaN и Infinity, MUST показывать понятное сообщение о пустом списке и MUST продолжать работать (добавление доступно).

#### Scenario: Все задачи удалены (T5)
- **WHEN** пользователь удаляет все задачи
- **THEN** итог 0 ч, прогресс 0%, в интерфейсе нет NaN или Infinity
- **AND** после добавления новой задачи трекер работает и пересчитывает метрики

### Requirement: Фильтр видимого списка
Система MUST предоставлять фильтр «Все», «Активные», «Выполненные». Фильтр MUST менять только видимый список; итоговые часы и прогресс MUST считаться по всем задачам и MUST NOT меняться от выбора фильтра. Фильтр MUST NOT менять данные.

#### Scenario: Фильтр «Активные» (T3)
- **WHEN** в стартовом наборе выбран фильтр «Активные»
- **THEN** в списке только «Практика» и «Повторение»
- **AND** всего 8 ч, выполнено 2 ч, прогресс остаётся 25%

#### Scenario: Фильтр «Выполненные»
- **WHEN** в стартовом наборе выбран фильтр «Выполненные»
- **THEN** в списке только «Чтение», прогресс остаётся 25%

#### Scenario: Фильтр без совпадений
- **WHEN** выбран фильтр «Выполненные», а выполненных задач нет
- **THEN** список пуст с понятным сообщением, метрики считаются по всем задачам

### Requirement: Адаптивный и подписанный интерфейс
Интерфейс MUST быть читаемым на ширине 390 px без горизонтальной прокрутки. Каждое поле ввода и каждая кнопка MUST иметь доступную подпись (видимый label или доступное имя).

#### Scenario: Узкий экран
- **WHEN** страница открыта в окне шириной 390 px
- **THEN** весь контент помещается по ширине, горизонтальной прокрутки нет

#### Scenario: Подписи элементов
- **WHEN** пользователь просматривает форму и список
- **THEN** у полей названия и часов есть label, у кнопок добавления, удаления и переключения статуса есть понятное имя

### Requirement: Автономность
Трекер MUST работать без сервера, сети, CDN, внешних библиотек и API-ключей.

#### Scenario: Работа без сети
- **WHEN** страница открыта при отключённой сети
- **THEN** все функции трекера доступны

### Requirement: Необязательное сохранение между перезапусками
Если реализовано сохранение в localStorage, система MUST восстанавливать задачи при повторном открытии, а при недоступном или повреждённом хранилище MUST показывать понятное сообщение и продолжать работу в памяти.

#### Scenario: Хранилище недоступно
- **WHEN** localStorage выбрасывает ошибку при чтении или записи
- **THEN** пользователь видит сообщение о работе без сохранения, а добавление, удаление и смена статуса продолжают работать
