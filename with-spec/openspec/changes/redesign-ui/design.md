# Design

## Context

Код из `build-tracker` уже есть, и это изменение его дорабатывает:
- `domain.mjs` — чистые функции задач, метрик, фильтра и валидации;
- `app.mjs` — состояние `{tasks, filter}`, `render()`, делегирование событий, адаптер localStorage с ключом `study-tracker.tasks.v1`;
- `index.html` — одна колонка; фильтр сделан через `<select>`; форма `novalidate` с кнопкой `type=submit`;
- `styles.css` — светлая mobile-first вёрстка.

Ограничения (redesign-brief.md): те же пять файлов, без внешних ресурсов, прежние тесты не трогать. Мотивация — см. proposal.md, требования — см. specs/tracker/spec.md.

## Goals / Non-Goals

**Goals:**
- Темы и акцент задаются через CSS-переменные, чтобы смена настроек была одной операцией без перерисовки списка.
- Логику настроек (нормализация, ограничение диапазонов, выбор цвета текста) вынести в чистые функции `domain.mjs` и покрыть тестами.
- Сохранить разделение «данные/расчёты — интерфейс» и поведение R1–R6.

**Non-Goals:**
- Модальная ловушка фокуса и полноценный менеджер диалогов: панель не модальная.
- Анимации сложнее CSS-переходов и keyframes.
- Изменение модели задачи и ключа хранения задач.

## Decisions

### D1. Модель настроек и чистые функции (`domain.mjs`)
```
Settings = { theme: 'dark' | 'light' | 'system',
             accent: { preset: 'lilac'|'blue'|'emerald'|'amber'|'coral'|null, h, s, l } }
```
- `ACCENT_PRESETS` — 5 пресетов с id, русским названием и `{h,s,l}` из брифа. `DEFAULT_SETTINGS` = `{ theme: 'system', accent: lilac }`.
- `normalizeSettings(raw)` → всегда корректный `Settings`:
  - неизвестная тема → `'system'`;
  - известный `preset` → значения берутся из пресета (защита от подмены);
  - `preset: null` → `h,s,l` ограничиваются `clampAccent`: h 0–360, s 0–100, l 20–80, нечисловые значения → значения по умолчанию (Сиреневый);
  - не объект или JSON-мусор → `DEFAULT_SETTINGS`.
- `clampAccent({h,s,l})` — ограничение и округление до целых.
- `accentTextColor({h,s,l})` → `'#000'` или `'#fff'`: HSL переводится в sRGB, считается относительная яркость по WCAG, выбирается цвет с большим контрастом. Для Янтарного выходит чёрный, для яркости 25% — белый.
- `resolveTheme(theme, prefersDark)` → `'dark' | 'light'`.
- `findPreset(accent)` — id пресета, если h/s/l совпадают, иначе `null`. Нужен, чтобы при движении ползунков отметка пресета снималась.
- Альтернатива: держать эту логику в `app.mjs` — отклонено, её нельзя было бы проверить в Node без DOM.

### D2. Темы и акцент через CSS-переменные
- На `<html>` ставятся `data-theme="dark|light"` (уже вычисленная тема) и переменные `--accent-h`, `--accent-s`, `--accent-l`, `--on-accent`. Из них собираются `--accent: hsl(var(--accent-h) var(--accent-s) var(--accent-l))` и полупрозрачные варианты для свечения, фокуса и подсветки.
- Палитры тем (`--bg`, `--card` из диапазона #141114–#1c181c, `--border: rgba(255,255,255,.08)`, `--text`, `--muted`) задаются в `:root[data-theme="dark"]` и `[data-theme="light"]`. Свечение фона — несколько `radial-gradient` с акцентом и тёплым сиреневым тоном.
- Без атрибута (до запуска JS) CSS выбирает тему по `@media (prefers-color-scheme)`, поэтому при теме по умолчанию нет вспышки.
- Тема «Системная» отслеживается через `matchMedia('(prefers-color-scheme: dark)')` и слушатель `change`, который пересчитывает `data-theme` только при `theme === 'system'`.
- Альтернатива: отдельные классы на каждый цвет — отклонено, «свой цвет» требует произвольных значений.

### D3. Раскладка и компоненты
- Шапка: `<h1>` «Учебные задачи <span class="accent-word">на неделю</span>», подзаголовок, справа круглая кнопка `aria-label="Настройки"` с inline SVG-шестерёнкой.
- Сетка: `display: grid`, одна колонка по умолчанию; при `@media (min-width: 900px)` — `grid-template-columns: minmax(0,5fr) minmax(0,7fr)`, «Итоги» и «Новая задача» слева, «Задачи» справа; контейнер `max-width: 1100px`.
- Типографика: `html { font-size: 17px }` (18 px от 900 px), заголовок `clamp(30px, 6vw, 36px)`, числа итогов `clamp(32px, 8vw, 40px)`, отступы карточек 20–28 px, радиус 22 px.
- Фильтр: `<select>` заменяется на `<fieldset>` с `<legend>` «Показать» и тремя `input type=radio` в виде таблеток (`:has(:checked)` или класс). `app.mjs` слушает `change` на fieldset; `filterTasks` и метрики не меняются.
- Строка задачи: прежняя разметка плюс бейдж статуса; флажок — `accent-color: var(--accent)`, увеличенный размер.
- Скрытые элементы: в `styles.css` явно `[hidden] { display: none !important }`, чтобы новые `display` не перебили атрибут.

### D4. Панель настроек
- Немодальная панель `<section id="settings-panel" role="dialog" aria-labelledby aria-modal="false" hidden>`, позиционирована под кнопкой; на узком экране занимает почти всю ширину (`width: min(360px, calc(100vw - 32px))`).
- Состояние открытия хранится в `app.mjs`; у кнопки `aria-expanded` и `aria-controls`. Закрытие: кнопка «Закрыть», `keydown` Escape на документе, `pointerdown` вне панели и вне кнопки. После закрытия фокус возвращается на «Настройки», при открытии переходит на первый элемент панели.
- Внутри: группа радиокнопок темы (таблетки «Тёмная/Светлая/Системная»), группа из 5 радиокнопок-кружков с `aria-label` пресета, блок «Свой цвет» с тремя `input type=range` с `<label>` и выводом значения (`<output>`), образец цвета.
  - Трек «Оттенок» — `linear-gradient` по 0–360°.
  - Треки насыщенности и яркости показывают градиент текущего оттенка.
- Событие `input` у ползунков сразу применяет цвет; `preset` становится `findPreset(...)`, отметка у кружков снимается.
- Альтернатива: `<dialog>` с `showModal()` — отклонено: модальная ловушка фокуса и фон-подложка не нужны, а клик вне `<dialog>` всё равно пришлось бы обрабатывать вручную.

### D5. Сохранение настроек
- Отдельный ключ `study-tracker.settings.v1`, тот же подход, что у задач: `try/catch`, при чтении `normalizeSettings(JSON.parse(raw))`, при ошибке — `DEFAULT_SETTINGS` и работа в памяти. Флаг доступности хранилища общий; сообщение о недоступности показывается один раз.
- Запись при каждом изменении темы или цвета. Во время движения ползунков пишется только последнее значение — по событию `change`, а не на каждый `input`.

### D6. Обратная связь при добавлении и Enter
- Enter: форма уже отправляется неявно (implicit submission) при Enter в текстовом поле, если в ней есть кнопка `type=submit`. Обработчик `submit` один для кнопки и Enter, поэтому валидация одна и та же. Решение — сохранить это поведение и закрепить его ручной проверкой; дополнительный `keydown` не нужен. Фокус после успеха уже возвращается в «Название».
- Подсветка: `app.mjs` запоминает `lastAddedId`; `renderTask` добавляет класс `task--new` с keyframes ~1 с (акцентный фон, затем прозрачный). Класс снимается по `animationend` или через `setTimeout(1000)`. Если новая задача скрыта фильтром «Выполненные», подсветки просто нет.
- Нажатие: `.btn--primary:active { transform: scale(.97) }`, свечение — `box-shadow` в цвете акцента.
- `@media (prefers-reduced-motion: reduce)` отключает `transition` и `animation` (подсветка — статичная рамка или ничего).

### D7. Тесты
- В `tests/acceptance.test.mjs` дописываются новые группы `describe`; существующие тесты не меняются и не удаляются.
- Что проверяют новые тесты:
  - `normalizeSettings`: неизвестная тема → `system`, мусор → по умолчанию, пресет восстанавливается из таблицы, свой цвет ограничивается (оттенок 400 → 360, яркость 95 → 80, яркость 5 → 20, насыщенность −10 → 0);
  - `accentTextColor`: Янтарный → `#000`, яркость 25% → `#fff`, для каждого пресета контраст выбранного цвета ≥ 4.5;
  - `resolveTheme` и `findPreset`.

## Risks / Trade-offs

- [Вспышка темы при сохранённом явном выборе: модуль выполняется после разбора HTML] → по умолчанию тема берётся из CSS-медиазапроса; для явного выбора вспышка короткая и допустима. Инлайновый скрипт, дублирующий логику, не добавляется.
- [Контраст `--muted` и бейджей в светлой теме] → подобрать значения с контрастом ≥ 4.5:1 и проверить вручную; текст на акценте выбирается функцией `accentTextColor`.
- [`:has()` поддерживается не во всех старых браузерах] → выбранную таблетку также помечать классом или стилем `input:checked + span`, не полагаясь только на `:has()`.
- [Клик вне панели совпадает с кликом по кнопке «Настройки» и сразу открывает панель снова] → кнопка исключается из проверки «вне панели», а повторное нажатие на неё переключает панель.
- [Ползунки с большим числом событий `input`] → применяется только запись CSS-переменных, без перерисовки списка; в хранилище пишется по `change`.
- [Браузер в этой среде не запускается] → внешний вид, темы, панель, Enter и 390 px проверяются вручную; в отчёте фактические проверки отделяются от предложенных.
