# Proposal

## Why

Дефект 01 (bugfix-01.md, воспроизведён в Chromium 147) проявляется в двух режимах:
- при открытии `index.html` через `file://` и в iframe `sandbox="allow-scripts"` (непрозрачный origin `null`) браузер блокирует ES-модуль `app.mjs` по CORS, и трекер не работает целиком;
- в iframe `sandbox="allow-scripts allow-same-origin"` без `allow-forms` блокируется отправка формы, поэтому задача не добавляется ни кнопкой, ни по Enter.

Обычное открытие через http-сервер работает. Но требование автономности (build-tracker) и ожидание «работает в любом способе открытия» нарушены. Причина — два решения в design: подключение через `type="module"` и добавление через `submit`. Их нужно уточнить в спецификации и заменить.

## What Changes

- Добавление задачи больше не зависит от отправки формы:
  - кнопка «Добавить» становится `type="button"` с обработчиком `click`;
  - Enter в полях «Название» и «Часы» обрабатывается `keydown` (без Shift и не во время IME-композиции, с `preventDefault`);
  - оба пути и запасной `submit` (тоже с `preventDefault`) вызывают одну функцию добавления с прежней валидацией.
- Браузер подключает классический скрипт `tracker.js` (`<script src="tracker.js" defer>`, без `type="module"`):
  - файл генерирует `build.mjs` на чистом Node (`node build.mjs`) из `domain.mjs` и `app.mjs`: убирает `import`/`export` и оборачивает код в IIFE;
  - `tracker.js` коммитится, вручную не редактируется;
  - исходники `domain.mjs` и `app.mjs` остаются источником истины, тесты по-прежнему импортируют `domain.mjs`.
- Автотест актуальности: результат сборки из текущих исходников совпадает с `tracker.js` побайтно, а сам `tracker.js` синтаксически корректен как классический скрипт.
- Хранилище при непрозрачном origin: если обращение к `window.localStorage` выбрасывает `SecurityError`, трекер работает в памяти без ошибок — задачи, настройки, панель.
- Новые файлы: `build.mjs` (скрипт сборки) и `tracker.js` (сгенерированный). Это осознанное исключение из ограничения redesign-brief «новых файлов кода не добавлять»: его прямо требует bugfix-01.md.

### Не входит в изменение

- Изменение правил и ожидаемых значений brief.md (R1–R6, T1–T5) и redesign-brief.md (D1–D3); удаление или ослабление прежних тестов.
- Внешние сборщики, бандлеры, минификация, npm-зависимости, `package.json`.
- Сервер, Service Worker, обходы CORS, альтернативные хранилища (IndexedDB, cookies) для непрозрачного origin.
- Изменение внешнего вида и раскладки.
- Автоматизированное браузерное тестирование: повторную проверку в трёх режимах выполняет оператор.

## Capabilities

### New Capabilities

- Нет.

### Modified Capabilities

- `tracker`: добавляются требования (только ADDED):
  - добавление без отправки формы — кнопка и Enter через обработчики;
  - работа без ES-модулей в браузере — классический `tracker.js`, собираемый `build.mjs`;
  - актуальность сборки, проверяемая тестом;
  - хранилище при непрозрачном origin.

  Существующие требования build-tracker и redesign-ui не меняются. Требование «Добавление по Enter» (redesign-ui) остаётся в силе; меняется только способ реализации из design.md redesign-ui (неявная отправка формы). Capability вводится незаархивированным `build-tracker`, поэтому порядок архивации такой: build-tracker → redesign-ui → fix-sandbox-input.

## Impact

- `index.html`: подключение `tracker.js` вместо `app.mjs`; кнопка «Добавить» с `type="button"`.
- `app.mjs`: функция добавления, обработчики `click` и `keydown`, запасной `submit` с `preventDefault`. Код по-прежнему исполняется в браузере только через `tracker.js`.
- `domain.mjs`: без изменения поведения. Ограничение — только именованные `export const/function`, без `export default` и реэкспортов (контракт сборки).
- Новые файлы: `build.mjs`, `tracker.js`.
- `tests/acceptance.test.mjs`: дописываются тесты сборки; прежние 51 тест не меняются.
- Рабочий порядок: после любой правки `domain.mjs` или `app.mjs` выполнить `node build.mjs`, иначе тест актуальности упадёт.
