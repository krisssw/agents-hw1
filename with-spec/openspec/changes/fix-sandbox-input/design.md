# Design

## Context

Текущее состояние кода после redesign-ui:
- `index.html` подключает `<script type="module" src="app.mjs">`;
- `app.mjs` импортирует из `./domain.mjs` один многострочный блок `import { … } from './domain.mjs';`;
- `domain.mjs` экспортирует только `export const …` и `export function …` (без `export default` и реэкспортов); его приватные имена — `idCounter`, `presetAccent`, `clampNumber`;
- добавление задачи идёт только через `submit` формы `#task-form` (кнопка `type="submit"`, Enter — неявная отправка);
- адаптер `storage` в `app.mjs` уже оборачивает `globalThis.localStorage.getItem/setItem` в `try/catch`.

Причины дефекта и ограничения описаны в proposal.md и bugfix-01.md. Требования — в specs/tracker/spec.md. Решения ниже заменяют два места прежних design.md:
- build-tracker D6 — подключение через `type="module"`;
- redesign-ui D6 — Enter через неявную отправку формы.

Требования прежних спецификаций не меняются.

## Goals / Non-Goals

**Goals:**
- Один путь добавления задачи (`addFromForm`), не зависящий от отправки формы.
- Классический `tracker.js`, детерминированно собираемый из исходников на чистом Node.
- Тест, который ловит устаревший `tracker.js`.
- Отсутствие необработанных ошибок при непрозрачном origin.

**Non-Goals:**
- Универсальный бандлер: сборка поддерживает только контракт этого проекта (раздел D3).
- Минификация, source maps, транспиляция синтаксиса.
- Отказ от `domain.mjs` и `app.mjs` как ES-модулей: они нужны тестам и как исходники.

## Decisions

### D1. Единая функция добавления и обработчики
- В `app.mjs` логика из обработчика `submit` выносится в `addFromForm()`: валидация через `validateTaskInput` → ошибки у полей и сохранение значений, либо `addTask`, подсветка, сброс, фокус в «Название».
- Кнопка «Добавить» получает `type="button"` и `click → addFromForm()`. Кнопок `type="submit"` в форме не остаётся, поэтому неявной отправки по Enter нет.
- `keydown` на полях «Название» и «Часы» → если `isEnterSubmit(event)`, то `event.preventDefault()` и `addFromForm()`.
- Форма остаётся (семантика и `novalidate`). Запасной `submit` → `event.preventDefault()` и `addFromForm()`. Двойного добавления нет: Enter уже отменён в `keydown`, а кнопок `type=submit` нет.
- Чистая функция в `domain.mjs`: `isEnterSubmit({ key, shiftKey, isComposing, keyCode })` → `key === 'Enter' && !shiftKey && !isComposing && keyCode !== 229` (229 — признак IME-композиции в Chromium). Её можно проверить в Node.
- Альтернатива: оставить `submit` и попросить добавить `allow-forms` в окно просмотра — отклонено, окно просмотра мы не контролируем.

### D2. Подключение классического скрипта
- `index.html`: `<script src="tracker.js" defer></script>` вместо `type="module"`. Классические скрипты загружаются через `file://` и при origin `null`, на них не действует CORS-проверка модулей.
- `defer` сохраняет порядок «DOM готов → код выполняется», как было у модуля.

### D3. Сборка `build.mjs`
- Модуль экспортирует чистую функцию `buildTracker({ domainSource, appSource }) → string` и константу `BANNER`. При прямом запуске (`node build.mjs`, проверка через `import.meta.url` и `process.argv[1]`) он читает исходники, собирает результат и записывает `tracker.js`: сначала во временный файл, затем переименовывает. При ошибке файл не перезаписывается, код выхода 1.
- Преобразование `domain.mjs`:
  - строки `^export (const|let|function|class) NAME` → без `export `, имена собираются;
  - любой другой `export` (`export default`, `export {`, `export *`) или любой `import` → ошибка с номером строки.
- Преобразование `app.mjs`:
  - ровно один блок `import { … } from './domain.mjs';` удаляется, имена из него разбираются;
  - каждое импортированное имя должно существовать среди экспортов `domain.mjs`, иначе ошибка;
  - другие `import`/`export` → ошибка.
- Форма результата: у каждого модуля своя область видимости, поэтому приватные имена не конфликтуют, а глобальных переменных нет.
  ```
  // BANNER: сгенерировано build.mjs из domain.mjs + app.mjs — не редактировать вручную; правьте исходники и запустите `node build.mjs`
  (function () {
    'use strict';
    const domain = (function () {
      // --- domain.mjs ---
      …
      return Object.freeze({ <экспорты по алфавиту> });
    })();
    (function () {
      const { <импорты app.mjs в исходном порядке> } = domain;
      // --- app.mjs ---
      …
    })();
  })();
  ```
- `'use strict'` сохраняет семантику модулей (они всегда strict).
- Детерминизм: нет дат и путей, переводы строк нормализуются к `\n`, порядок имён фиксирован.
- Альтернатива: склеить файлы в одну область видимости без обёрток — отклонено из-за риска коллизии имён и утечки в `window`. Ещё одна альтернатива — esbuild или rollup — отклонена: внешние зависимости запрещены.

### D4. Тесты сборки (`tests/acceptance.test.mjs`, дописываются)
- **Актуальность:** `buildTracker(текущие исходники) === readFile('tracker.js')`. Сообщение при расхождении: «tracker.js устарел — выполните `node build.mjs`».
- **Синтаксис:**
  - `new vm.Script(tracker)` компилирует файл как классический скрипт (с `import`/`export` компиляция упала бы);
  - `spawnSync(process.execPath, ['--check', 'tracker.js'])` возвращает 0;
  - в файле нет `type="module"`-зависимостей: нет строк `^\s*(import|export)\b`, есть BANNER.
- **Чувствительность:** изменение `appSource` меняет результат сборки (тест падал бы при правке без пересборки).
- **Детерминизм:** два вызова на одних и тех же исходниках дают одинаковый результат.
- **Ошибки:** `export default`, посторонний `import` и импорт несуществующего имени приводят к исключению с понятным текстом.
- **Изоляция:** выполнение `tracker.js` в `vm`-контексте с минимальной заглушкой DOM не создаёт новых глобальных имён и не бросает исключений. Заглушка остаётся внутри теста, отдельного файла нет.
- **Клавиша:** `isEnterSubmit` для Enter, Shift+Enter, `isComposing`, `keyCode 229` и другой клавиши.
- **index.html:** подключает `tracker.js` без `type="module"`; у кнопки «Добавить» `type="button"`.

### D5. Хранилище при непрозрачном origin
- Каждое обращение к `globalThis.localStorage` (включая сам геттер, который при origin `null` бросает `SecurityError`) остаётся только внутри `try/catch` адаптера `storage`. Вне адаптера нет `typeof localStorage` и проверок «есть ли хранилище».
- Первая ошибка переводит адаптер в режим памяти (`available = false`) и один раз показывает сообщение. Дальше хранилище не трогается.

## Risks / Trade-offs

- [Забыли пересобрать после правки исходников] → тест актуальности падает с подсказкой `node build.mjs`; в REPORT и tasks зафиксирован порядок «правка → сборка → тесты».
- [Регулярные выражения сборки не поймут новый синтаксис (например, `export async function`, top-level `await`)] → сборка явно отвергает неизвестные `import`/`export`; при необходимости контракт расширяется отдельным изменением.
- [`keyCode` устарел] → используется только как дополнительный признак IME рядом с `isComposing`.
- [Firefox и `file://`: собственные правила для localStorage] → любая ошибка ведёт в режим памяти; повторную проверку проводит оператор.
- [`tracker.js` дублирует код в репозитории] → файл помечен как сгенерированный, правки в нём ловит тест актуальности.
- [Браузер в этой среде не запускается] → поведение в `file://` и sandbox-iframe подтверждает оператор; в отчёте фактические проверки отделяются от предложенных.
