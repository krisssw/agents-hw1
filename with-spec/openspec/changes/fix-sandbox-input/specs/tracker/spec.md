# Spec Delta

## ADDED Requirements

### Requirement: Добавление кнопкой без отправки формы
Кнопка «Добавить» MUST добавлять задачу через собственный обработчик нажатия и MUST NOT зависеть от отправки HTML-формы. Добавление MUST использовать ту же валидацию и поведение, что и раньше: ошибка у поля и сохранение введённых значений при некорректном вводе, сброс формы и фокус в «Название» после успеха.

#### Scenario: Кнопка в iframe без allow-forms
- **WHEN** трекер открыт в iframe `sandbox="allow-scripts allow-same-origin"` без `allow-forms`, введены «Тест» и 2, нажата кнопка «Добавить»
- **THEN** задача «Тест» добавлена, всего 10 ч, прогресс 20%, в консоли нет сообщения `Blocked form submission`

#### Scenario: Кнопка при ошибке ввода
- **WHEN** название пустое, часы 2 и нажата кнопка «Добавить»
- **THEN** задача не добавлена, у поля названия видна ошибка, значения полей сохранены

### Requirement: Добавление по Enter без отправки формы
Нажатие Enter в поле «Название» или «Часы» MUST добавлять задачу через обработчик клавиатуры, вызывающий ту же функцию добавления, что и кнопка. Обработчик MUST отменять действие браузера по умолчанию и MUST NOT срабатывать при нажатом Shift или во время IME-композиции.

#### Scenario: Enter в поле «Часы» в sandbox-iframe
- **WHEN** трекер открыт в iframe `sandbox="allow-scripts allow-same-origin"`, введены «Тест» и 2, нажат Enter в поле «Часы»
- **THEN** задача добавлена, всего 10 ч, прогресс 20%, фокус в поле «Название»

#### Scenario: Enter в поле «Название»
- **WHEN** введены «Тест» и 2, нажат Enter в поле «Название»
- **THEN** задача добавлена так же, как кнопкой

#### Scenario: Shift+Enter и IME-композиция
- **WHEN** пользователь нажимает Shift+Enter или Enter во время IME-композиции
- **THEN** задача не добавляется и ошибка не показывается

### Requirement: Запасная обработка отправки формы
Если поля остаются внутри элемента формы, событие отправки формы MUST отменяться и MUST вызывать ту же функцию добавления, а страница MUST NOT перезагружаться или переходить по адресу. Одно действие пользователя MUST добавлять не более одной задачи.

#### Scenario: Обычное открытие через http-сервер
- **WHEN** трекер открыт через http-сервер, введены «Тест» и 2, нажат Enter в поле «Часы»
- **THEN** добавлена ровно одна задача «Тест», страница не перезагружалась

### Requirement: Работа без ES-модулей в браузере
Страница MUST подключать логику одним классическим скриптом `tracker.js` без `type="module"` и MUST полностью работать без загрузки ES-модулей браузером, в том числе через `file://` и в iframe с непрозрачным origin. Должно работать всё: добавление, удаление, смена статуса, фильтр, итоги и панель настроек.

#### Scenario: Открытие через file://
- **WHEN** `index.html` открыт двойным щелчком (`file://`) в Chromium
- **THEN** в консоли нет ошибки CORS про загрузку скрипта; стартовые итоги 8 ч / 2 ч / 25%; «Тест» 2 ч добавляется кнопкой и по Enter; шестерёнка открывает панель настроек

#### Scenario: iframe sandbox="allow-scripts"
- **WHEN** `index.html` открыт в iframe `sandbox="allow-scripts"` (origin `null`)
- **THEN** T1–T5 проходят, задача добавляется кнопкой и по Enter, панель настроек открывается и закрывается

#### Scenario: Обычное открытие через http-сервер
- **WHEN** `index.html` открыт через http-сервер
- **THEN** поведение совпадает с прежним: T1–T5, Enter, кнопка и настройки работают

### Requirement: Сборка tracker.js из исходников
`tracker.js` MUST генерироваться командой `node build.mjs` из `domain.mjs` и `app.mjs` на Node без внешних зависимостей. Результат MUST быть классическим скриптом без `import` и `export`, в котором весь код изолирован в собственной области видимости (без глобальных переменных), и MUST содержать пометку о том, что файл сгенерирован и вручную не редактируется. Сборка MUST быть детерминированной.

#### Scenario: Повторная сборка
- **WHEN** `node build.mjs` запущен дважды без изменения исходников
- **THEN** `tracker.js` побайтно одинаков, внешних пакетов не требуется

#### Scenario: Неподдерживаемый синтаксис
- **WHEN** в исходниках появляется конструкция, которую сборка не умеет преобразовать (например, `export default` или импорт другого модуля)
- **THEN** `node build.mjs` завершается с ошибкой и понятным сообщением, `tracker.js` не перезаписывается

### Requirement: Исходники остаются источником истины
`domain.mjs` и `app.mjs` MUST оставаться исходными файлами логики; автотесты MUST по-прежнему импортировать `domain.mjs`. Поведение в браузере MUST определяться только кодом из этих исходников, попавшим в `tracker.js`.

#### Scenario: Тесты импортируют domain.mjs
- **WHEN** запускается `node --test tests/acceptance.test.mjs`
- **THEN** прежние тесты импортируют `domain.mjs` и проходят без изменений

### Requirement: Тест актуальности сборки
Автотесты MUST проверять, что `tracker.js` совпадает с результатом сборки из текущих `domain.mjs` и `app.mjs` и является синтаксически корректным классическим скриптом. Если исходник изменён без пересборки, тест MUST падать с сообщением о необходимости выполнить `node build.mjs`.

#### Scenario: Сборка актуальна
- **WHEN** после `node build.mjs` запускаются автотесты
- **THEN** тест актуальности проходит

#### Scenario: Исходник изменён без пересборки
- **WHEN** в `app.mjs` внесена правка, а `node build.mjs` не запускался
- **THEN** тест актуальности падает и сообщает, что нужно выполнить `node build.mjs`

### Requirement: Хранилище при непрозрачном origin
Если обращение к `window.localStorage` или его методам выбрасывает исключение (в том числе `SecurityError` при origin `null`), трекер MUST продолжать работать в памяти без необработанных ошибок. Задачи, тема, цвет выделения и панель настроек MUST работать, а пользователь MUST видеть понятное сообщение о том, что сохранение недоступно.

#### Scenario: iframe sandbox="allow-scripts"
- **WHEN** трекер открыт в iframe `sandbox="allow-scripts"`, где доступ к `window.localStorage` выбрасывает `SecurityError`
- **THEN** в консоли нет необработанных ошибок, видно сообщение о работе без сохранения, задачи добавляются, тема и цвет переключаются

#### Scenario: Ошибка при записи
- **WHEN** чтение из localStorage удалось, а запись выбрасывает исключение
- **THEN** изменение применяется в памяти, сообщение показывается один раз, работа продолжается

### Requirement: Совместимость с прежними правилами
Исправление MUST NOT менять правила brief.md (R1–R6), redesign-brief.md (D1–D3) и значения T1–T5; все прежние автотесты MUST оставаться без изменений и проходить.

#### Scenario: Регрессия
- **WHEN** после исправления запускаются автотесты
- **THEN** прежние 51 тест проходят без изменений, вместе с новыми тестами сборки
